# 阶段二：独立服务与存储基础

交付版本：standalone 0.2.0。记录日期：2026-10-30。领域及工具契约仍为 1.0.0。

## 1 交付边界

现在可以在没有安装或启动 DSH 的情况下，运行一个本机服务，将合成或由调用方提交的回合保存到真实 SQLite 文件。消息、任务与幂等回执原子提交，重启后仍可查询状态和继续处理。内部存储 API 可以暂存候选、检查版本和证据、原子发布完整记忆修订。

本阶段没有接入人物仓库、MCP、DeepSeek 或自动整理器。启动服务不会自行从聊天窗口采集消息，也不会自动理解情绪、抽取经历或压缩归档。接收消息之后，任务默认保持 queued；测试通过内部 API 提供人工候选或明确的 no-change 结果。不能用 accepted 回执声称模型已经处理完毕。

原 DSH 插件入口、依赖、代码和运行配置均不属于本次改动。服务不会读取 `DSH_HOME`，不会导入原 DSH 文件。

## 2 目录和模块

```text
standalone/
├─ src/
│  ├─ cli.ts                    初始化、前台启动、状态、停止、令牌、备份恢复
│  ├─ config.ts                 独立路径及配置校验
│  ├─ server.ts                 本机管理 HTTP，不是 MCP
│  ├─ runtime/
│  │  ├─ store.ts               事务编排、凭据、幂等、候选发布
│  │  ├─ backup.ts              一致性快照及新目录恢复
│  │  └─ errors.ts              可识别错误码
│  ├─ db/
│  │  ├─ connection.ts          WAL、迁移哈希、事务、单写入者锁
│  │  ├─ objects.ts             不可变完整载荷和字节校验
│  │  ├─ context.ts             从数据库构造可信校验上下文
│  │  ├─ observations.ts        回合、来源编辑、任务和连续水位
│  │  ├─ jobs.ts                持久队列、租约代次和有界重试
│  │  ├─ memory-writer.ts       完整修订和可重建查询投影
│  │  └─ migrations/002-runtime.sql
│  ├─ domain/                   阶段一领域定义
│  └─ contracts/                阶段一 Schema 和语义守卫
├─ contracts/database/001-initial.sql
├─ tests/runtime-*.test.ts      文件库、故障、备份及独立进程测试
├─ tsconfig.build.json
└─ dist/                       构建生成，不提交
```

运行目录用 `--home` 显式指定，其次为 `FISH_MEMORY_HOME`，否则是用户目录下的 `.fish-companion`。配置、SQLite 和档案不随源码目录移动。SQLite 文件应位于本机磁盘。

```text
<FISH_MEMORY_HOME>/
├─ config.json                 一个 companion、用户和角色的固定绑定
├─ memory.sqlite               权威数据库；运行时可能有 -wal / -shm
├─ writer.lock.sqlite          SQLite 持有的进程锁，退出自动释放
├─ admin-token                 初始管理令牌明文，仅留本机文件
├─ service.json                当前监听地址、PID 和实例 ID，不含令牌
├─ archives/objects/           后续归档位置，当前不生成归档
├─ archives/staging/
├─ imports/
├─ backups/
└─ logs/                       预留；当前不会写入对话日志
```

`writer.lock.sqlite` 文件存在不代表服务仍运行；判据是 SQLite 的操作系统锁。不要通过删除该文件“解锁”。强制结束后可直接重新 serve，旧 `service.json` 会在成功取得写入者锁并监听之后替换。

## 3 安装和日常运行

固定验证环境为 Windows、Node.js 24.19.0、npm 11.17.0。依赖由本子包 lockfile 固定。代码使用 Node 原生 SQLite 和原生 TypeScript 执行；构建输出普通 JavaScript。

在 standalone 目录执行：

```powershell
npm ci --ignore-scripts
npm run check

$env:FISH_MEMORY_HOME = Join-Path $env:USERPROFILE '.fish-companion-dev'
npm run cli -- init --user-name '用户' --character-name '角色'
npm run cli -- serve
```

`serve` 是前台进程，不安装开机启动，不自动启动 DSH。另开终端设置相同的 `FISH_MEMORY_HOME`，执行：

```powershell
npm run cli -- status
npm run cli -- stop
```

也可每条命令使用 `--home '绝对路径'`。初始默认端口为 43117；初始化测试目录时可以 `init --port 0` 由系统分配。已有配置的 init 是复用而不是覆盖；配置端口只能在停止后编辑。配置格式或数据库绑定不匹配时拒绝启动，不创建空库掩盖错误。

编译运行：

```powershell
npm run build
node dist/cli.js serve --home '你的独立运行目录'
```

部署时需保留 `dist/`、`contracts/database/001-initial.sql`、package 文件与生产依赖。仅复制 dist 不构成完整发行包。构建会将 002 迁移复制到 dist；001 保留在契约目录。

## 4 身份和本地入口

初始化为用户、角色及 companion 生成独立 ID；同名不是同一个人物。当前为一个用户和一个角色，不提供多人物管理。角色默认的 `persona_reference=unconfigured` 是接入占位，不包含或修改角色主性格。

所有凭据在数据库中只保存 SHA-256。CLI 只输出令牌文件路径，不输出令牌；`admin-token` 不进入备份。文件使用独占创建和可用的最小文件模式，Windows 上仍继承运行目录的账户 ACL，不宣称 POSIX mode 等价于 Windows 私有 ACL。

服务停止时可以发放额外凭据：

```powershell
npm run cli -- token-issue --capability observe --out '一个尚不存在的令牌文件绝对路径'
```

能力为 read、observe、user_edit、admin，admin 包含前三项。user_edit 的具体编辑接口在后续阶段实现。令牌不能自行指定 companion；数据库固定绑定生效。撤销后每次新操作会再次校验；幂等重放也不能绕过撤销。

HTTP 仅绑定 `127.0.0.1`，要求匹配的 Host，拒绝带 Origin 的浏览器请求。除 health 外均需 `Authorization: Bearer <令牌>`。JSON 请求上限 1 MiB；默认请求超时 10 秒。

| 路由 | 能力 | 当前作用 |
| --- | --- | --- |
| GET /health | 无 | 最小存活信息与实例 ID |
| GET /status | read | 数据量、队列、水位与阶段状态，不返回原话或令牌 |
| POST /observe | observe | 使用阶段一 observe_turn 输入，返回持久回执和 replayed 标记 |
| GET /memory/{id} | read | 返回当前、已发布、有效的完整修订 |
| POST /admin/backup | admin | JSON `{}` 自动选目录，或 `{ "destination": "绝对路径" }` |
| POST /admin/shutdown | admin | JSON `{}`；停止接收新连接并等待已有工作结束 |

这些是阶段二的管理和存储验证入口，不是 MCP tools/call。六个工具的正式输出 envelope 仍以阶段一契约为准，MCP 层将在阶段三转换和校验。当前不提供纠正、撤回、检索或任意 SQL 的 HTTP 接口。

## 5 持久化与失败语义

- 001 初始 SQL 保持阶段一内容；002 是新增运行迁移。记录迁移编号、名称和 SQL 字节哈希。历史漂移、未知新版本或不连续计划均拒绝。新增迁移与历史记录在一个事务提交。
- 单个运行目录仅允许一个遵守入口的写入进程；只读 SQLite 连接可在 WAL 模式并行读取。不要绕过服务直接写 SQLite。
- 一个 observe 请求的消息版本、任务、回合回执、连续水位和幂等回执一起提交。事务中断不产生成功回执。相同凭据、工具和 request_id、相同载荷返回首次保存的原始结果；载荷不同报 IDEMPOTENCY_CONFLICT。首次结果可能仍为 pending，最新状态应查询 status。
- 来源会话、回合、消息的外部 ID 经命名空间映射，两个会话中的相同 turn-1/user-1 不冲突。数据库另外约束回执的 turn 必须属于同一个会话和分支。
- 消息版本和原始内容对象不可变。当前阶段只接收 main 分支；编辑保留已有消息身份、角色和位置，变更的消息必须升版本，链版本恰好加一。编辑使相关当前修订失效，并重新排队该会话的有效回合。分支继承、删消息、宿主流式钩子留给阶段三。
- accepted_through 和 processed_through 都从第一个回合开始连续推进。有空洞、未完成或失败任务时不跳过。接收不是处理完成。
- 每次认领有独立 token、递增 generation 和到期时间；续约、完成和候选提交均检查持久化输入和当前租约。过期后重试，达到上限则 failed。重启不会直接信任旧工作者；未过期租约等待到期，随后恢复。模型工作者尚未启动，因此没有后台定时消费器。
- 候选先暂存；发布时重新加载目标版本、撤回代次、来源及证据，完整修订、证据关联、查询投影、任务完成和水位在同一事务提交。旧候选不能覆盖新版本。
- 完整规范 JSON 修订是权威载荷，typed 表及 search_documents 是查询投影，不能从概要重建完整记忆。当前尚无检索引擎。新修订会登记本次输入及全部引用证据的消息依赖，复用旧证据也受后续来源编辑约束。

## 6 备份与恢复

```powershell
npm run cli -- backup --out '一个尚不存在的备份目录绝对路径'
npm run cli -- restore --from '备份目录绝对路径' --home '一个尚不存在的新运行目录绝对路径'
```

运行中 backup 通过本机管理接口执行；停止后也可离线执行。旧服务元数据失联时，离线备份仍必须取得写入者锁。备份期间暂停受控写入，调用 SQLite 在线备份 API 取得一致性快照；不会只拷贝活动主数据库文件。快照检查 SQLite 完整性、外键、迁移哈希及每个不可变内容对象的长度与哈希。配置和数据库写入后，最后发布带两者哈希与字节长度的 manifest.json。

当前 `fish-backup-v1` 明确标记 `inline-only`。检测到任何归档记录或非内联内容都会失败，不能漏包后仍声称成功。阶段七须扩展格式及测试，复制快照引用的不可变包并校验，不可无声放宽此限制。格式清单提供意外损坏检测，不是防恶意改写的数字签名；备份当前也不加密。

恢复先检查整个备份，拒绝覆盖已有目录；只允许新目录，原服务可以继续工作。恢复目录留有 `restore.incomplete` 标记，数据库验证、旧凭据禁用、未完成任务隔离及新管理令牌写入全部完成后才移除。中途失败保留不可启动的目录，下一次应选择新目录，不自动删除资料。

旧凭据和旧租约在恢复实例中不再有效。恢复命令返回新的 admin-token 路径；使用新 `--home` 明确启动恢复实例，不会自动切换原目录。备份中的历史回执仍保留，但需要新凭据调用；不能用旧凭据绕过恢复隔离。

## 7 测试与阶段一的兼容

阶段一仍允许测试、修正和补充样本。修改领域结构或语义时，应同时维护 Schema、人工期望、语义守卫及兼容说明；再运行 schemas:write 和 check。不能为了通过运行测试删除来源、撤回或身份约束。本阶段只给 tools.ts 补充运行实现使用的类型导出，工具 JSON Schema 和生成样本内容未改变。

`npm run check` 包含类型检查、阶段一生成物漂移检查、全部测试、JavaScript 构建及编译产物 CLI 冒烟测试。所有文件库使用系统临时目录和合成资料，不访问个人记忆，不调用模型。主要新增验证为：

| 范围 | 实际验证 |
| --- | --- |
| 数据库 | 文件 WAL、唯一写入者、只读并发、迁移重跑/哈希漂移/失败回滚 |
| 回合 | 重启重放、重复载荷、不同载荷冲突、跨会话 ID、乱序连续水位 |
| 候选 | 完整修订持久化、原子失败重试、后返回候选版本冲突、来源编辑失效 |
| 租约 | 到期隔离、伪造输入拒绝、有界重试、真实进程死亡后恢复 |
| 进程 | init/serve/status/stop、重复启动、强制结束及重启、DSH 哨兵保持不变 |
| 备份 | 运行中一致性、新目录恢复、旧凭据与旧租约失效、写入暂停、坏文件拒绝、归档遗漏拒绝 |

其中进程中断样本在子进程内持久认领任务，然后开启尚未提交的事务，强制结束进程；重开后检查该事务无残留、数据库完整且过期任务能重新认领。此测试不等同于断电或磁盘硬件故障验证。

本次验收结果：79 项测试通过（阶段一原有 54 项、阶段二新增 25 项），类型检查与生成物检查通过；编译后的 JavaScript CLI 完成 init、离线 backup、restore 和重新打开。故意损坏服务元数据的样本会输出预期的 METADATA_CLEANUP_FAILED 警告，同时验证数据库及进程锁仍可正确关闭。原仓库 24 个已跟踪文件的 SHA-256 与本阶段开始时一致。

## 8 后续实施顺序

下一阶段以本存储层作为唯一写入口实现 MCP 和宿主适配：先确认目标人物仓库与钩子，再补 stdio 到本地服务的桥接、六个正式工具、分支与流式终止语义。随后接 DeepSeek 提供候选，进入经历抽取和动态修订；情绪理解及安慰策略、尘封压缩和自动唤醒按开发方案各阶段实施。

不能把当前人工候选测试通过视为真实模型理解准确，也不能把预留 archives 目录视为已实现无损压缩。
